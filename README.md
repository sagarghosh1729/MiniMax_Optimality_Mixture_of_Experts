# Mixture-of-Experts Simulation Suite

This repository contains the simulation code, numerical results, and figures used to study **feed-forward Mixture-of-Experts (MoE) regression models** and their empirical behavior relative to theoretical estimation-error bounds.

The experiments compare three routing mechanisms:

1. **General / dense MoE routing** — all experts contribute through a softmax gate.
2. **Top-k routing** — only the $k$ experts with the largest gate logits are selected.
3. **Top-p routing** — experts are selected according to cumulative softmax probability mass.

The simulations investigate how test RMSE, training RMSE, empirical $L^2$ quantities, and theoretical bounds vary with the number of training samples.

## 1. Simulation Pipeline

The overall experimental pipeline is:

```text
Gaussian Input X
       │
       ▼
Frozen Transformer
       │
       ▼
Clean Target Y_clean
       │
       ▼
Gaussian Noise
       │
       ▼
Observed Target Y
       │
       ▼
Mixture-of-Experts Regression
       │
       ├── General Routing
       ├── Top-k Routing
       └── Top-p Routing
       │
       ▼
RMSE + Empirical L² Envelopes + Theoretical Bound
```

The input is generated as

\[
X \sim \mathcal{N}(0,I),
\]

and the target is generated by passing the input through a frozen Transformer and adding Gaussian noise:

\[
Y = Y_{\mathrm{clean}} + \varepsilon.
\]

The resulting dataset is used as a controlled regression problem for evaluating different MoE routing mechanisms.

## 2. Dataset Generation

`Python Codes/generate_dataset.py` generates the synthetic regression datasets.

### Default configuration

- Number of samples: `1,000,000`
- Input dimension: `32`
- Transformer hidden dimension: `32`
- Transformer encoder layers: `8`
- Attention heads: `8`
- Batch size: `1024`
- Gaussian noise standard deviation: `0.0005`
- Random seed: `1234`

The script automatically uses:

- **Apple Silicon MPS**, when available
- **CUDA**, when available
- **CPU**, otherwise

### Generate a dataset

From the repository root:

```bash
python "Python Codes/generate_dataset.py"
```

Custom parameters can be supplied, for example:

```bash
python "Python Codes/generate_dataset.py" \
    --n_samples 1000000 \
    --input_dim 32 \
    --hidden_dim 32 \
    --batch_size 1024 \
    --noise 0.0005 \
    --seed 1234
```

The generated datasets are saved in PyTorch `.pt` format. These files can become very large and are therefore ignored by Git.

## 3. Mixture-of-Experts Architecture

Each experiment uses a feed-forward MoE with:

- `4` experts
- Expert hidden dimension: `256`
- One hidden layer
- GELU nonlinearities
- A neural gating network
- Standardized input and output variables


The gate is a neural network that produces a score for each expert.

The final MoE prediction is a weighted combination of the selected expert outputs.

---

## 4. General MoE

`Python Codes/train_general_moe.py`

The general MoE uses a standard softmax gate.

All four experts can contribute to every prediction.

The experiment evaluates the model over **100 different training-set sizes**, ranging from approximately 1% to 100% of the available training data.

---

## 5. Top-$k$ MoE

`Python Codes/train_top-k_moe.py`

The Top-$k$ model first computes the gate logits and selects the $k$ experts with the largest logits.

The current implementation uses

\[
K=4,\qquad k=2.
\]

The selected logits are normalized with a softmax. 

All non-selected experts receive zero weight.

The value of $k$ can be changed in:

```python
r = 2
```

inside `train_top-k_moe.py`.

---

## 6. Top-$p$ MoE

`Python Codes/train_top-p_moe.py`

The Top-$p$ router sorts experts according to their softmax probabilities and selects experts until the cumulative probability exceeds the specified threshold.

The current implementation uses

\[
p=0.7.
\]

The selected experts are then renormalized using a softmax over their original gate logits.

The value of $p$ can be changed through:

```python
given_p = 0.7
```

inside `train_top-p_moe.py`.

Unlike Top-$k$, the number of active experts can vary from sample to sample.

---

## 7. Training Procedure

For each routing mechanism:

1. Load the generated dataset.
2. Standardize both $X$ and $Y$.
3. Randomly split the data into:
   - **80% training**
   - **20% testing**
4. Construct 100 training-set sizes from 1% to 100% of the training data.
5. Train a new MoE for each training-set size.
6. Record:
   - Test RMSE
   - Training RMSE
   - Empirical expert $L^2$ measures
   - Empirical gate $L^2$ measure
   - Theoretical bound
   - Additional routing statistics for Top-$p$
7. Save the resulting statistics as CSV files.
8. Save the best-performing model checkpoint.

The training uses the **AdamW-based PyTorch optimization pipeline** implemented in the corresponding training scripts.

---

## 8. Empirical $L^2$ Quantities and Theoretical Bounds

The training scripts compute empirical quantities associated with the expert and gating classes.

For the experts, the implementation computes an empirical $L^2$ magnitude for each expert and records the maximum.

A corresponding empirical quantity is computed for the gate.

These quantities are then used in the theoretical estimation-error bound implemented in the simulation code.

The resulting bound is compared directly against the observed test RMSE as the training-set size increases.

## 11. Figures

The `Figures` directory contains plots generated from the simulation results.

For each routing mechanism, figures are provided for:

### RMSE vs. theoretical bounds

These plots compare:

- Test RMSE
- Training RMSE
- Theoretical bound

as a function of the number of training samples.

### First-order difference bounds

These figures are used to examine the behavior of the empirical quantities and the corresponding theoretical bounds through first-order differences.

## 13. Running the Experiments

After generating the required dataset, run the desired experiment:

### General routing

```bash
python "Python Codes/train_general_moe.py"
```

### Top-$k$ routing

```bash
python "Python Codes/train_top-k_moe.py"
```

### Top-$p$ routing

```bash
python "Python Codes/train_top-p_moe.py"
```

> **Important:** The current training scripts contain local absolute paths to the dataset and result directories. If the repository is cloned to another machine or directory, update these paths before running the scripts.

For example, paths of the form

```text
/Users/.../Simulations/Generated_Datasets/...
```

should be changed to paths appropriate for the local environment.

---

## 14. Reproducibility

Random seeds are explicitly set in the scripts.

The experiments also use deterministic dataset splitting based on the generated random permutation.

Exact reproducibility may nevertheless depend on the hardware backend (CPU, CUDA, or Apple MPS) and the corresponding PyTorch implementation.
